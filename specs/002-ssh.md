# 002 — SSH e bootstrap

## Estado atual (funcionando)

```
Host windows-host
    HostName windows-host.local
    IdentityFile ~/.ssh/id_ed25519_windows
    IdentitiesOnly yes
    AddKeysToAgent yes
    User user
```

Chave ed25519 dedicada, **com passphrase**, guardada em sessão pelo
`gcr-ssh-agent` do GNOME (`SSH_AUTH_SOCK=/run/user/1000/gcr/ssh`): pede
uma vez por login e depois serve a automação sem nunca expor a frase.

No Windows, o `windows-ssh.ps1` instala o OpenSSH Server, abre a 22 no
perfil Privado e põe o PowerShell como shell.

## As duas armadilhas já pagas

**`administrators_authorized_keys`.** Para conta no grupo
Administrators, o sshd do Windows **ignora** `~/.ssh/authorized_keys`.
Lê `C:\ProgramData\ssh\administrators_authorized_keys` e **descarta em
silêncio** se a ACL não for restrita — daí o
`icacls /inheritance:r` com permissão só para Administrators e SYSTEM.

**`known_hosts` amarrado a IP.** Trocar IP por nome fez tudo falhar com
`Host key verification failed`. A correção certa não é `accept-new` às
cegas: é copiar a *mesma* chave já confiável para o novo nome e
conferir fingerprint. Receita no README.

## O que falta: `POST /api/bootstrap/{id}`

Provisionar a outra máquina sem copiar `.ps1` na mão. Sequência
idempotente, cada passo verificando antes de agir:

1. **Alcance** — resolve `windows-host.local`, testa 22.
2. **Identidade** — garante a chave; se faltar, gera e instala
   (pedindo a passphrase ao usuário, nunca escolhendo uma).
3. **Capacidades** — detecta `winget`, versão do Windows, se é Pro.
4. **Pacotes** — Deskflow e KDE Connect via `winget install`, com
   `--accept-*-agreements`. Já validado hoje: o KDE Connect entrou
   assim, hash verificado.
5. **Firewall** — as regras que **os instaladores não criam**. O KDE
   Connect escutava 1716 e nenhuma regra `*KDE*` existia; o Deskflow
   idem na 24800. Esse passo não é opcional, é a causa nº 1 de
   "instalei e não funciona".
6. **Autostart** — atalho em `shell:startup` (logon, não serviço: o
   servidor precisa de sessão de usuário para capturar input).
7. **Verificar** — reportar o que mudou e o que já estava certo.

## Limite estrutural: isolamento de sessão

Comando por SSH no Windows **não alcança a sessão interativa**.
Verificado duas vezes hoje:

- Lançar `kdeconnect-indicator.exe` por SSH não abre nada no desktop;
  tentar via `schtasks /it` também não subiu.
- `Set-Clipboard` por SSH escreve num clipboard que o `kdeconnectd` da
  sessão do usuário não vê — o `Get-Clipboard` da mesma sessão SSH
  devolve o valor, o que torna o teste enganosamente "verde".

**Consequência de projeto:** o bootstrap faz instalação, firewall,
registro e arquivos. Qualquer coisa que precise da sessão gráfica tem
que rodar **no agente**, dentro daquela sessão — é metade da razão de
existir um `logid-agent` no Windows em vez de só SSH.
